# Error Taxonomy

The Propel backend strictly maps application domain errors to specific HTTP status codes and canonical error string details. 

Global exception handlers in `app/main.py` enforce this mapping systematically to prevent arbitrary exception leakage and maintain API consistency.

## Canonical Error Codes

### 404 Not Found
Generated by `NotFoundError("RESOURCE", id)` which automatically formats to `{RESOURCE}_NOT_FOUND`.

| Error Code | Trigger |
|---|---|
| `USER_NOT_FOUND` | User ID is missing in database |
| `USER_STATS_NOT_FOUND` | User Stats missing for a requested user |
| `ATTEMPT_NOT_FOUND` | Attempt ID does not exist |
| `LESSON_NOT_FOUND` | Lesson ID does not exist |

### 403 Forbidden
Generated by `ForbiddenError("REASON")`.

| Error Code | Trigger |
|---|---|
| `ATTEMPT_FORBIDDEN` | Requesting user tries to modify an attempt belonging to someone else |
| `SKILL_LOCKED` | Requesting user attempts to start a lesson for a skill they have not yet unlocked |

### 409 Conflict
Generated by `ConflictError("REASON")`.

| Error Code | Trigger |
|---|---|
| `ATTEMPT_ALREADY_TERMINATED` | Submitting answers or completing an attempt that is already `failed` or `completed` |
| `LESSON_INCOMPLETE` | Attempting to complete a lesson when exercises remain unanswered |
| `CORRUPTED_LESSON_STATE` | Internal data violation (e.g., attempt points to out-of-bounds exercise index) |
| `CORRUPTED_USER_STATS` | Internal data violation (e.g., unexpected missing stats during calculation) |
| `EXERCISE_NOT_CURRENT` | Submitting an answer for an exercise ID that does not match the attempt's current cursor |
| `EXERCISE_NOT_IN_LESSON` | Submitting an answer for an exercise ID that doesn't belong to the lesson |
| `EXERCISE_ALREADY_ANSWERED` | Concurrency check prevents answering the same exercise twice |
| `LESSON_HAS_NO_EXERCISES` | Starting a lesson that has no seeded exercises |
| `NOT_ENOUGH_GEMS` | Attempting to refill hearts with insufficient gems |
| `HEARTS_ALREADY_FULL` | Attempting to refill hearts when already at max capacity |
| `UNSUPPORTED_EXERCISE_TYPE` | Unknown exercise type string encountered |

### 422 Unprocessable Entity
Generated by `InvalidPayloadError("REASON")`.

| Error Code | Trigger |
|---|---|
| `INVALID_ANSWER_PAYLOAD` | Answer payload type does not match the expected evaluator type (e.g., array vs string) |

---

## Global Handler Verification

The `app/main.py` file maps domain exceptions perfectly to the schema:

- `NotFoundError` → `404` (`{"detail": f"{exc.resource}_NOT_FOUND"}`)
- `ForbiddenError` → `403` (`{"detail": exc.reason}`)
- `ConflictError` → `409` (`{"detail": exc.reason}`)
- `InvalidPayloadError` → `422` (`{"detail": exc.reason}`)

*No inconsistent strings (like `user_not_found`, `USER_NOTEXIST`, or `USER_MISSING`) were found in the codebase. Every single domain error uses exactly one canonical uppercase snake_case string.*
